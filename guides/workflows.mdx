Workflows are HTTP automation scripts — Python is the glue layer for constructing HTTP requests, calling endpoints via `ctx.http`, and parsing responses. This guide covers common patterns, the builtin workflows, code generation, and testing.

## The Pattern

Every workflow follows the same pattern:

1. Read credentials from `ctx.secrets.get("KEY")`
2. Build an HTTP request with indicator/alert data from `ctx.indicator` and `ctx.alert`
3. Call the endpoint via `ctx.http` (an `httpx.AsyncClient`)
4. Check the response and return `WorkflowResult.ok()` or `WorkflowResult.fail()`

```python
from app.workflows.context import WorkflowContext, WorkflowResult

async def run(ctx: WorkflowContext) -> WorkflowResult:
    api_key = ctx.secrets.get("MY_API_KEY")
    if not api_key:
        return WorkflowResult.fail("MY_API_KEY is not set")

    try:
        resp = await ctx.http.post(
            "https://api.example.com/action",
            json={"indicator": ctx.indicator.value, "type": ctx.indicator.type},
            headers={"Authorization": f"Bearer {api_key}"}
        )
    except Exception as exc:
        return WorkflowResult.fail(f"Request failed: {exc}")

    if resp.status_code >= 400:
        return WorkflowResult.fail(f"API returned {resp.status_code}")
    return WorkflowResult.ok("Action completed", data=resp.json())
```

## Common Use Cases

### Generic Webhook

POST indicator/alert context to any URL — SOAR platforms, ticketing systems, or custom endpoints:

```python
async def run(ctx: WorkflowContext) -> WorkflowResult:
    url = ctx.secrets.get("WEBHOOK_URL")
    if not url:
        return WorkflowResult.fail("WEBHOOK_URL is not set")

    payload = {
        "indicator_type": ctx.indicator.type,
        "indicator_value": ctx.indicator.value,
        "malice": ctx.indicator.malice,
    }
    if ctx.alert:
        payload["alert"] = {"title": ctx.alert.title, "severity": ctx.alert.severity}

    try:
        resp = await ctx.http.post(url, json=payload)
    except Exception as exc:
        return WorkflowResult.fail(f"Request failed: {exc}")

    if resp.status_code >= 400:
        return WorkflowResult.fail(f"Webhook returned {resp.status_code}")
    return WorkflowResult.ok(f"Webhook delivered (HTTP {resp.status_code})")
```

### REST API with Bearer Token

Call ServiceNow, Jira, PagerDuty, or any REST API using an API key from environment variables:

```python
async def run(ctx: WorkflowContext) -> WorkflowResult:
    instance = ctx.secrets.get("SERVICENOW_INSTANCE")
    token = ctx.secrets.get("SERVICENOW_API_TOKEN")
    if not instance or not token:
        return WorkflowResult.fail("ServiceNow credentials not set")

    try:
        resp = await ctx.http.post(
            f"https://{instance}/api/now/table/incident",
            headers={"Authorization": f"Bearer {token}", "Content-Type": "application/json"},
            json={"short_description": f"SOC: {ctx.indicator.value}", "urgency": "2"},
        )
    except Exception as exc:
        return WorkflowResult.fail(f"Request failed: {exc}")

    if resp.status_code not in (200, 201):
        return WorkflowResult.fail(f"ServiceNow returned {resp.status_code}")
    number = resp.json().get("result", {}).get("number", "unknown")
    return WorkflowResult.ok(f"Incident created: {number}", data={"number": number})
```

### AWS Lambda / Azure Logic App

Invoke serverless functions via HTTP — no AWS/Azure SDK needed:

```python
async def run(ctx: WorkflowContext) -> WorkflowResult:
    url = ctx.secrets.get("LAMBDA_FUNCTION_URL")  # or LOGIC_APP_TRIGGER_URL
    if not url:
        return WorkflowResult.fail("Function URL is not set")

    event = {"indicator": ctx.indicator.value, "type": ctx.indicator.type}
    try:
        resp = await ctx.http.post(url, json=event)
    except Exception as exc:
        return WorkflowResult.fail(f"Invocation failed: {exc}")

    if resp.status_code >= 400:
        return WorkflowResult.fail(f"Returned {resp.status_code}")
    return WorkflowResult.ok("Function invoked", data=resp.json())
```

### HMAC-Signed Webhook

POST with a cryptographic signature for receivers that verify request authenticity:

```python
import hashlib
import hmac
import json

async def run(ctx: WorkflowContext) -> WorkflowResult:
    url = ctx.secrets.get("SIGNED_WEBHOOK_URL")
    secret = ctx.secrets.get("SIGNED_WEBHOOK_SECRET")
    if not url or not secret:
        return WorkflowResult.fail("URL and secret must be set")

    payload = {"indicator": ctx.indicator.value, "type": ctx.indicator.type}
    body = json.dumps(payload, sort_keys=True).encode("utf-8")
    sig = hmac.new(secret.encode(), body, hashlib.sha256).hexdigest()

    try:
        resp = await ctx.http.post(
            url, content=body,
            headers={"Content-Type": "application/json", "X-Signature-256": f"sha256={sig}"},
        )
    except Exception as exc:
        return WorkflowResult.fail(f"Request failed: {exc}")

    if resp.status_code >= 400:
        return WorkflowResult.fail(f"Returned {resp.status_code}")
    return WorkflowResult.ok("Signed webhook delivered")
```

## Builtin Workflows

Calseta ships with 9 pre-built workflows for Okta and Microsoft Entra identity lifecycle management:

**Okta** (requires `OKTA_DOMAIN` + `OKTA_API_TOKEN`):
- Revoke All Sessions — terminates all active sessions (low risk)
- Suspend User — blocks all sign-in attempts (high risk)
- Unsuspend User — restores a suspended account (medium risk)
- Reset Password — sends a password reset email (medium risk)
- Force Password Expiry — requires new password at next login (low risk)

**Entra** (requires `ENTRA_TENANT_ID` + `ENTRA_CLIENT_ID` + `ENTRA_CLIENT_SECRET`):
- Revoke Sign-in Sessions — invalidates refresh tokens (low risk)
- Disable Account — sets accountEnabled=false (high risk)
- Enable Account — re-enables a disabled account (medium risk)
- Force MFA Re-registration — deletes all registered auth methods (high risk)

All builtins require approval when triggered by an AI agent.

## Code Generation

Describe what you want in plain English, and Calseta generates valid workflow code:

```bash
curl -X POST http://localhost:8000/v1/workflows/generate \
  -H "Authorization: Bearer cai_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "description": "Add a malicious IP to our Cloudflare WAF block list",
    "indicator_types": ["ip"]
  }'
```

The generated code is AST-validated before being returned. Review it, then save via `POST /v1/workflows`. Requires `ANTHROPIC_API_KEY`.

## Testing

Run a workflow with mock HTTP responses — no real external calls:

```bash
curl -X POST http://localhost:8000/v1/workflows/{uuid}/test \
  -H "Authorization: Bearer cai_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "indicator_type": "ip",
    "indicator_value": "203.0.113.42",
    "mock_responses": [
      {
        "url_pattern": "https://api.example.com/*",
        "status_code": 200,
        "body": {"result": "blocked"}
      }
    ]
  }'
```

## Approval Gate

Set `approval_mode` on a workflow to control when approval is required:

- `"always"` — all triggers (human and agent) require approval
- `"agent_only"` — only agent-triggered executions require approval; humans bypass the gate
- `"never"` — no approval required

When the gate fires, execution pauses until a human approves or rejects via REST API, Slack buttons, or Teams.

Agent-triggered requests must include `reason` and `confidence` fields.
